Каждый проект это папка, которая растет по мере того, как появляется информация. `README.md` это единственная точка входа.

## Куда что класть

| Что | Куда |
|---|---|
| Обзор, статус, сроки, следующие шаги | `Проекты/{name}/README.md` |
| Рабочие заметки, которые ведет {Name} | `Проекты/{name}/заметки/{topic}.md` |
| Исследования | `Проекты/{name}/исследования/{topic}.md` |
| Бриф, техническое задание, требования | `Проекты/{name}/брифы/{name}.md` |
| Черновики, сценарии, тексты | `Проекты/{name}/черновики/{name}.md` |
| Идеи | `Проекты/{name}/идеи/{name}.md` |
| Отзывы и правки | `Проекты/{name}/отзывы/{name}.md` |
| Изображения и медиа | `Проекты/{name}/медиа/` |
| Старые материалы этого проекта | `Проекты/{name}/архив/` |

Названия папок пишутся строчными буквами через дефис, без номеров в начале (`исследования/`, а не `01-Research/`). Проект может завести свою папку, если ни одна из этих не подходит.

## Как устроен README

1. Блок информации (ниже) с `description`.
2. `## Что это`: одна-две строки, со ссылкой на [[цели]].
3. `## Статус и следующий шаг`: где проект сейчас и какой следующий шаг.
4. `## Как это работает`: только если сюда что-то пишется автоматически (задача по расписанию, скрипт).
5. `## Где что лежит`: только когда появились подпапки. Небольшая таблица со ссылкой на каждую.

## Блок информации (frontmatter)

```yaml
---
type: notes
date: 2026-10-13
status: active
project: Website-Redesign
tags: [website-redesign, notes]
---
```

- `type`: `project` (README, у него еще есть `created`, `updated` и `description`), `notes`, `research`, `brief`, `draft`, `idea`, `feedback`, `plan`.
- `status`: `active`, `paused` или `done`. Статус README и есть статус проекта.
- `project`: название папки проекта.
- `tags`: сначала проект, потом тип.

## Правила

- Новый проект это только `README.md`. Подпапки создавай, только когда появляется то, что в них нужно положить, и ставь на них ссылки из README.
- README это оглавление. Не повторяй в нем содержимое подпапок.
- Внутри проекта не бывает `CLAUDE.md`. Правила для одного проекта пиши ниже, в разделе «Правила для отдельных проектов».
- Указывай `project:` в блоке информации каждой связанной заметки.
- Завершенный проект переезжает в `Память/архив/{name}/`, только когда {Name} об этом скажет.
- Каждый проект должен работать на какую-то цель из [[цели]]. Во время проверки отмечай цели без проектов и проекты без целей.
