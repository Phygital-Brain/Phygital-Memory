プロジェクトは1つずつフォルダーになっていて、情報が増えるにつれて育っていきます。入口は `README.md` ひとつだけです。

## 振り分け

| 内容 | 置き場所 |
|---|---|
| 概要、状況、締め切り、次にやること | `プロジェクト/{name}/README.md` |
| {Name}さんの作業メモ | `プロジェクト/{name}/メモ/{topic}.md` |
| リサーチ | `プロジェクト/{name}/リサーチ/{topic}.md` |
| 依頼内容、仕様、要件 | `プロジェクト/{name}/依頼内容/{name}.md` |
| 下書き、台本、文章 | `プロジェクト/{name}/下書き/{name}.md` |
| アイデア | `プロジェクト/{name}/アイデア/{name}.md` |
| フィードバック | `プロジェクト/{name}/フィードバック/{name}.md` |
| 画像やメディア | `プロジェクト/{name}/素材/` |
| このプロジェクトの古い資料 | `プロジェクト/{name}/アーカイブ/` |

フォルダー名は、英字なら小文字とハイフンつなぎにし、番号はつけません（`01-Research/` ではなく `リサーチ/`）。どれにも当てはまらないときは、プロジェクトごとに独自のフォルダーを追加してかまいません。

## READMEの構成

1. 情報ブロック（下を参照）。`description` つき。
2. `## 概要`：一、二行で。[[目標]] にリンクします。
3. `## 状況と次の一歩`：今どこまで進んでいるか、次の一歩。
4. `## 自動で動いているもの`：何かが自動でここに書き込む場合だけ（予定タスク、スクリプトなど）。
5. `## ファイルの場所`：サブフォルダーができてから。それぞれへのリンクを小さな表にします。

## 情報ブロック（frontmatter）

```yaml
---
type: notes
date: 2026-10-13
status: active
project: Website-Redesign
tags: [website-redesign, notes]
---
```

- `type`：`project`（READMEのこと。`created`、`updated`、`description` もつけます）、`notes`、`research`、`brief`、`draft`、`idea`、`feedback`、`plan`。
- `status`：`active`、`paused`、`done`。READMEの状態が、そのプロジェクトの状態です。
- `project`：プロジェクトのフォルダー名。
- `tags`：プロジェクト、次に種類。

## ルール

- 新しいプロジェクトは `README.md` だけで始めます。サブフォルダーは、それが必要な内容が来たときだけ作り、READMEからリンクします。
- READMEは目次です。サブフォルダーの中身をくり返して書かないでください。
- プロジェクトの中に `CLAUDE.md` は置きません。1つのプロジェクトだけのルールは、下の「プロジェクトごとのルール」に書きます。
- 関係するノートにはすべて、情報ブロックに `project:` を入れます。
- 終わったプロジェクトを `記録/アーカイブ/{name}/` に移すのは、{Name}さんがそう言ったときだけです。
- どのプロジェクトも [[目標]] にある目標のどれかにつながるようにします。総点検では、プロジェクトのない目標と、目標のないプロジェクトを指摘してください。
