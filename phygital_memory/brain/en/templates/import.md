Brings notes from other apps into this brain, any time after the setup. How to export from each app: https://github.com/Phygital-Brain/phygital-brain/blob/main/docs/importing.md

Trigger: "bring in my old notes", "import these notes", or the same in {Language}. Also when {Name} drops in an export (a Notion folder, Google Docs, Apple Notes text, Evernote files, Markdown files).

## 1. Read, change nothing

Read everything {Name} gave you. For a big export, ask which part to start with ("your client notes first?") and work in parts of about 30 notes.

Skip what doesn't belong: passwords, keys, tokens and private numbers (root rules 25 and 26). Never copy those into the brain. Tell {Name} which files you skipped and why.

## 2. Make a plan

For each piece, decide its home using the Knowledge Routing table in the root `CLAUDE.md`: a project, a person or company, a decision, research, a library item, an About fact, or leave it out (old, empty or duplicate). Search the brain first, so a person or project that already has a note gets updated instead of a second note.

Show the plan in a short table: the source, where it goes, new note or update. Put "leave out" items in their own list.

## 3. Wait for a yes

Ask (click options when possible): `Bring them all in` · `Change the plan` · `Cancel`. Creating new notes needs this yes (root rule 9).

## 4. File

Before you write, make a backup of every note you'll change (see Backups and Undo in the root `CLAUDE.md`).

- Use each folder's info block (its `CLAUDE.md`) and the compiled-truth format for About and Relationships pages.
- Weave `[[links]]` to people, companies and projects into the text.
- Keep {Name}'s words. Shorten, don't rewrite.
- Old dates stay as they were: put them in the evidence lines, not in today's note.

## 5. Finish

Log one line in today's daily note: what was imported, how many notes were made and updated. Then suggest a check-up ("check up my brain") to catch duplicates and missing links.
