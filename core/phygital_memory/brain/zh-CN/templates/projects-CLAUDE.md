每个项目都是一个文件夹，随着信息增多慢慢长大。`README.md` 是唯一的入口。

## 归类

| 内容 | 放到 |
|---|---|
| 概况、现状、截止日期、下一步 | `项目/{name}/README.md` |
| {Name} 的工作笔记 | `项目/{name}/笔记/{topic}.md` |
| 调研 | `项目/{name}/调研/{topic}.md` |
| 需求简报、规格、要求 | `项目/{name}/需求简报/{name}.md` |
| 草稿、脚本、文字内容 | `项目/{name}/草稿/{name}.md` |
| 想法 | `项目/{name}/想法/{name}.md` |
| 反馈 | `项目/{name}/反馈/{name}.md` |
| 图片和媒体 | `项目/{name}/素材/` |
| 这个项目的旧资料 | `项目/{name}/归档/` |

文件夹名不加数字前缀（用 `调研/`，不用 `01-Research/`），英文字母一律小写，词之间用连字符。如果这些都不合适，项目可以自己加文件夹。

## README 结构

1. 信息块（见下文），要有 `description`。
2. `## 简介`：一两句话，链接到 [[目标]]。
3. `## 现状和下一步`：进展到哪了，下一步做什么。
4. `## 运行方式`：只有当有自动程序往这里写东西时才加（定时任务、脚本）。
5. `## 文件在哪`：只有建了子文件夹以后才加。用一张小表链接每个子文件夹。

## 信息块（frontmatter）

```yaml
---
type: notes
date: 2026-10-13
status: active
project: Website-Redesign
tags: [website-redesign, notes]
---
```

- `type`：`project`（README，另外还有 `created`、`updated` 和 `description`）、`notes`、`research`、`brief`、`draft`、`idea`、`feedback`、`plan`。
- `status`：`active`、`paused` 或 `done`。README 的状态就是项目的状态。
- `project`：项目文件夹的名字。
- `tags`：先写项目，再写类型。

## 规则

- 新项目只有一个 `README.md`。只有来了需要子文件夹的内容时，才建子文件夹，并在 README 里链接过去。
- README 就是目录。不要在里面重复子文件夹的内容。
- 项目里面不放 `CLAUDE.md`。只针对某个项目的规则，写在下面的“单个项目的规则”里。
- 每篇相关笔记的信息块里都要有 `project:`。
- 只有 {Name} 说了，已完成的项目才移到 `记忆/归档/{name}/`。
- 每个项目都应该为 [[目标]] 里的某个目标服务。体检时，标出没有项目的目标，和没有目标的项目。
