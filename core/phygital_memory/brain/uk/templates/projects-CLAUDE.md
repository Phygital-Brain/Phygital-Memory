Кожен проєкт це папка, яка росте, коли надходить інформація. `README.md` є єдиною точкою входу.

## Що куди класти

| Що | Куди |
|---|---|
| Огляд, стан, дедлайн, наступні кроки | `Проєкти/{name}/README.md` |
| Робочі нотатки, які пише {Name} | `Проєкти/{name}/нотатки/{topic}.md` |
| Дослідження | `Проєкти/{name}/дослідження/{topic}.md` |
| Бриф, технічне завдання, вимоги | `Проєкти/{name}/брифи/{name}.md` |
| Чернетки, сценарії, тексти | `Проєкти/{name}/чернетки/{name}.md` |
| Ідеї | `Проєкти/{name}/ідеї/{name}.md` |
| Відгуки | `Проєкти/{name}/відгуки/{name}.md` |
| Зображення й медіа | `Проєкти/{name}/медіа/` |
| Старі матеріали цього проєкту | `Проєкти/{name}/архів/` |

Назви папок пишуться малими літерами через дефіс, без номерів спереду (`дослідження/`, а не `01-Research/`). Проєкт може додати власну папку, якщо жодна з цих не підходить.

## Як влаштований README

1. Інфоблок (нижче), з `description`.
2. `## Що це`: один-два рядки з посиланням на [[цілі]].
3. `## Стан і наступний крок`: де проєкт зараз і наступний крок.
4. `## Як це працює`: лише якщо сюди щось пише автоматично (завдання за розкладом, скрипт).
5. `## Де що лежить`: лише коли з'являться підпапки. Невелика таблиця з посиланням на кожну.

## Інфоблок (frontmatter)

```yaml
---
type: notes
date: 2026-10-13
status: active
project: Website-Redesign
tags: [website-redesign, notes]
---
```

- `type`: `project` (README, де також є `created`, `updated` і `description`), `notes`, `research`, `brief`, `draft`, `idea`, `feedback`, `plan`.
- `status`: `active`, `paused` або `done`. Статус README є статусом проєкту.
- `project`: назва папки проєкту.
- `tags`: проєкт, потім тип.

## Правила

- Новий проєкт це лише `README.md`. Створюй підпапки тільки тоді, коли з'являється вміст, якому вони потрібні, і став на них посилання з README.
- README це покажчик. Не повторюй у ньому вміст підпапок.
- Жодного `CLAUDE.md` усередині проєкту. Правила для одного проєкту йдуть у розділ «Правила для окремих проєктів» нижче.
- Вказуй `project:` в інфоблоці кожної пов'язаної нотатки.
- Завершений проєкт переїжджає в `Пам'ять/архів/{name}/` лише тоді, коли {Name} про це скаже.
- Кожен проєкт має працювати на якусь мету з [[цілі]]. Під час перевірки познач цілі без проєкту і проєкти без мети.
